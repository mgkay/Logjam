Logjam

Logjam is a Julia package for logistics engineering, providing tools for:

  • Facility Location: Discrete optimization algorithms for facility location problems, including Uncapacitated Facility Location (UFL) and p-Median construction and improvement heuristics.
  • Transportation Costing: Formulas for estimating LTL & TL freight rates, calculating minimum charges, and evaluating total logistics costs (TLC).
  • Network Analysis: Routing and topology tools for the FAF5 highway network and OpenStreetMap road networks, including shortest paths and automatic facility connectors.
  • Vehicle Routing: Algorithms for multi-stop route optimization, featuring savings-based construction and local search improvement methods.
  • Spatial Data: A gazetteer of U.S. administrative boundaries and points, including Cities, Counties, ZIP codes (3- and 5-digit), Census tracts, and CBSA/CSA definitions.
  • Geocoding: Forward geocoding (loc2lonlat) from place names, postal codes, or street addresses to coordinates, and reverse geocoding (lonlat2loc) from coordinates to nearest named places. Street-address geocoding uses the Nominatim API via an optional extension.
  • Distance Metrics: Unified distance calculation utilities supporting Rectilinear (L₁), Euclidean (L₂), and Great Circle (Haversine) metrics.
  • Mapping: Geographic visualization with GeoMakie, including FCLASS-based road network rendering with OSM Carto-inspired styling, route overlays, and facility location plots.

The sections below follow the order of the course: location, transportation, distances, road networks, routing, inventory, data and geocoding, maps, and display. Each opens with what its functions are for, and where an example can run offline when the manual is built, it is run and its output shown.

Extensions

Logjam draws maps with GeoMakie and the Makie backend the caller loads, CairoMakie in the course (makemap leaves the active backend's settings as the caller set them). Five optional extensions are available:

Map Extension

makemap, plotroads! and dcf are the map extension's, which GeoMakie loads (using CairoMakie, GeoMakie; CairoMakie draws). Called without it, each is a MethodError that says what to load.

using CairoMakie, GeoMakie        # Triggers LogjamMapExt extension
using Logjam

Makie Extension

aligntext(ax, x, y, labels), which places labels clear of everything drawn in an axis, and the route and shipment drawing plotroute! and plotshmt! are the Makie extension's, which Makie loads: CairoMakie alone is enough, and GeoMakie loads it too. They work on a plain Axis and on the GeoAxis of makemap. Called without it, plotroute! and plotshmt! are each a MethodError that says what to load.

using CairoMakie                  # Triggers LogjamMakieExt extension
using Logjam

OSM Extension

To download OpenStreetMap road networks (osm_roads), load LightOSM before Logjam:

using LightOSM                    # Triggers LogjamOSMExt extension
using Logjam

bbox = mapbbox(stops_lon, stops_lat; xexpand=0.1, yexpand=0.1)
nodes, links = osm_roads(bbox; cache_dir = "osm")  # saved there; read from there next time, without LightOSM

Nominatim Extension

For street-address geocoding via the OpenStreetMap Nominatim API, load HTTP and JSON3 before Logjam:

using HTTP, JSON3  # Triggers LogjamNominatimExt extension
using Logjam

stops = DataFrame(STREET=["123 Main St"], CITY=["Raleigh"], STATE=[:NC])
gc = loc2lonlat(stops)  # Geocodes via Nominatim with city/state fallback

Optimization Extension

Logjam.TSP (Lecture 5.1's TSP formulation) and Logjam.binpack (Lecture 2.7's bin packing model) solve their models with HiGHS through JuMP, and snapvals reads a solved model's variables, when JuMP and HiGHS are both loaded. Called without them, TSP and binpack are each a MethodError that says what to load. Logjam.subtours, which TSP calls, needs neither.

using Logjam

Location Functions

Discrete facility location optimization using construction and improvement heuristics.

Construction Heuristics

Logjam.ufladd — Function
ufladd(k, C; y=Int[], p=nothing) -> (Vector{Int}, Float64, SparseMatrixCSC)

Greedy ADD construction heuristic for uncapacitated facility location.

Iteratively opens the new facility (NF) giving the greatest cost reduction until no improvement is possible. With p, it opens NFs until exactly p are open, whether or not each one lowers the cost (Matlog: "add exactly p NFs").

Arguments

  • k: Fixed cost. Scalar (same cost at every NF site) or length-n vector, k[i] = cost of opening an NF at candidate site i. Must be non-negative.
  • C: n×m variable-cost matrix over n candidate NF sites and m existing facilities (EFs); C[i,j] = cost of serving EF j from an NF at site i.
  • y: indices of the initially-open NF sites (default: empty — start from scratch). The caller's vector is never changed.
  • p: the number of NFs to open (default: nothing, no target: add while the cost falls). This is a target and not a cap: the call opens p sites even where the cost rises. Must be between 1 and n.

Returns

  • (y, TC, W): indices of the open NF sites, sorted; total cost TC = sum(k[y]) + sum(C[allocated]); and the n×m sparse allocation matrix W, W[i,j] = 1 if EF j is served by the NF at site i (a tie goes to the lower site index).

An error is thrown for a k of the wrong length or with a negative entry, a y that is out of range or repeats a site, and a p outside 1:n.

Example

Example 8.8 in Francis, Facility Layout and Location, 2nd ed. (Daskin, Network and Discrete Location, 1995, Fig. 7.2).

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y, TC, W = ufladd(k, C)
(y, TC)

# output

([2, 6], 32.0)

Starting from the open site y = [1] on the same data (Matlog's ufladd(k, C, 1)): the sites come back sorted and the caller's y0 is left as it was.

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y0 = [1]
y, TC, W = ufladd(k, C; y = y0)
(y0, y, TC)

# output

([1], [1, 4], 32.0)

p = 3 opens exactly three sites, one more than the unconstrained ADD stops at (Matlog's ufladd(k, C, [], 3)):

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y, TC, W = ufladd(k, C; p = 3)
(y, TC)

# output

([2, 4, 6], 32.0)

Logjam.ufldrop — Function
ufldrop(k, C; y=nothing, p=nothing) -> (Vector{Int}, Float64, SparseMatrixCSC)

Greedy DROP construction heuristic for uncapacitated facility location.

Starts with every new facility (NF) open and iteratively closes the one giving the greatest cost reduction until no improvement is possible. With p, it closes NFs until exactly p remain, whether or not each closure lowers the cost.

Arguments

  • k: Fixed cost. Scalar (same cost at every NF site) or length-n vector, k[i] = cost of opening an NF at candidate site i. Must be non-negative.
  • C: n×m variable-cost matrix over n candidate NF sites and m existing facilities (EFs); C[i,j] = cost of serving EF j from an NF at site i.
  • y: indices of the initially-open NF sites (default: all NF sites open). The caller's vector is never changed.
  • p: the number of NFs to leave open (default: nothing, drop until no improvement). Must be between 1 and n.

Returns

  • (y, TC, W): indices of the open NF sites, sorted; total cost TC = sum(k[y]) + sum(C[allocated]); and the n×m sparse allocation matrix W, W[i,j] = 1 if EF j is served by the NF at site i (a tie goes to the lower site index).

Example

Example 8.8 in Francis, Facility Layout and Location, 2nd ed. (Daskin, Network and Discrete Location, 1995, Fig. 7.3). DROP stops at a different local optimum than ADD.

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y, TC, W = ufldrop(k, C)
(y, TC)

# output

([2, 4, 6], 32.0)

p = 4 stops at four open sites on the same data, at a higher cost than the unconstrained DROP reaches (Matlog's ufldrop(k, C, [], 4)):

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y, TC, W = ufldrop(k, C; p = 4)
(y, TC)

# output

([1, 2, 4, 6], 37.0)

Improvement Heuristics

Logjam.uflxchg — Function
uflxchg(k, C, y) -> (Vector{Int}, Float64, SparseMatrixCSC)

Pairwise EXCHANGE improvement heuristic for uncapacitated facility location.

Steepest-descent swaps — close one open new facility (NF), open one closed — from a starting set y until a local optimum is reached: when it returns, no single swap of an open site for a closed one lowers the total cost. The swap preserves the number of open NFs, so y sets the cardinality.

With only one open site the procedure makes no swap and returns y as given, even where another single site costs less. This is Matlog's rule (uflxchg.m starts its loop only when length(y) > 1), so the local-optimality promise above holds for two or more open sites. Use ufladd or pmedian to choose a single site.

Arguments

  • k: Fixed cost. Scalar (same cost at every NF site) or length-n vector (see ufladd).
  • C: n×m variable-cost matrix over n candidate NF sites and m existing facilities (EFs); C[i,j] = cost of serving EF j from an NF at site i.
  • y: indices of the starting open NF sites (required — exchange improves this set), any vector of integers: a range such as 2:3, or Int32 indices, as ufladd and ufldrop take theirs (v0.3.1, A8). The caller's vector is never changed.

Returns

  • (y, TC, W): indices of the improved open NF sites, sorted; total cost TC = sum(k[y]) + sum(C[allocated]); and the n×m sparse allocation matrix W, W[i,j] = 1 if EF j is served by the NF at site i.

Each pass scans every (open site, closed site) pair of the set it starts with and makes the best swap, the first of equal ones in the order of y and then of the closed sites.

Example

Improve the ADD solution to Example 8.8 (Francis, 2nd ed.; Daskin, Fig. 7.5): the swap takes the starting set [2, 6] (TC 32.0) to [3, 6] (TC 31.0).

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y0, _, _ = ufladd(k, C)          # ADD gives the starting set
y, TC, W = uflxchg(k, C, y0)
(y0, y, TC)

# output

([2, 6], [3, 6], 31.0)

The starting set may be a range, here sites 1 to 2 (TC 37), improved to the same [3, 6]:

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y, TC, W = uflxchg(k, C, 1:2)
(y, TC)

# output

([3, 6], 31.0)

Hybrid Methods

Logjam.ufl — Function
ufl(k, C; verbose=true) -> (Vector{Int}, Float64, SparseMatrixCSC)

Hybrid UFL heuristic combining ADD, EXCHANGE, and DROP.

Iterates ADD → EXCHANGE → (ADD vs DROP, take best) until no improvement. Typically finds a better solution than any single procedure alone. With the default verbose=true, prints the per-step Add/Xchg/Drop cost trace, the one trace format of the location family (pmedian and ala print theirs the same way). The sites are returned sorted.

Arguments

  • k: Fixed cost. Scalar (same cost at every NF site) or length-n vector (see ufladd).
  • C: n×m variable-cost matrix over n candidate new-facility (NF) sites and m existing facilities (EFs); C[i,j] = cost of serving EF j from an NF at site i.
  • verbose: print the per-step cost trace (default: true).

Returns

  • (y, TC, W): indices of the best open NF sites found, sorted; total cost TC = sum(k[y]) + sum(C[allocated]); and the n×m sparse allocation matrix W, W[i,j] = 1 if EF j is served by the NF at site i.

Example

Example 8.8 in Francis, Facility Layout and Location, 2nd ed. The hybrid improves on ADD (32.0) and DROP (32.0) alone.

k = [8, 8, 10, 8, 9, 8]
C = [ 0  3  7 10  6  4
      3  0  4  7  6  7
      7  4  0  3  6  8
     10  7  3  0  7  8
      6  6  6  7  0  2
      4  7  8  8  2  0]
y, TC, W = ufl(k, C)
(y, TC)

# output

  Add: 32.0
 Xchg: 31.0
  Add: 31.0
 Drop: 31.0
([3, 6], 31.0)

References

  • R.L. Francis, L.F. McGinnis, J.A. White, Facility Layout and Location: An Analytical Approach, 2nd ed., Ex. 8.8; M.S. Daskin, Network and Discrete Location, 1995. Ported from Matlog ufl.

Logjam.pmedian — Function
pmedian(p, C; verbose=true, construct=:add) -> (Vector{Int}, Float64, SparseMatrixCSC)

p-median facility location: open exactly p new facilities (NFs; no fixed costs) to minimize total assignment cost. Constructs a set of p sites with ufladd (k = 0), then improves it with uflxchg. With construct = :both it also constructs from ufldrop and improves that, and keeps the cheaper of the two (Matlog's pmedian).

Arguments

  • p: number of NFs to open, between 1 and n.
  • C: n×m variable-cost matrix over n candidate NF sites and m existing facilities (EFs); C[i,j] = cost of serving EF j from an NF at site i.
  • verbose: print the per-step cost trace, in the format of ufl (default: true, as at v0.2.8).
  • construct: :add (default) improves ADD's p sites. With many candidate sites and few facilities (n ≫ p) DROP starts from all n sites and is the slow direction, so the default uses ADD alone. :both runs ADD → EXCHANGE and DROP → EXCHANGE and keeps the better; it can only improve the answer, and matters when n is close to p.

Returns

  • (y, TC, W): indices of the p open NF sites, sorted; total cost TC = sum(C[allocated]) (transport only, no fixed costs); and the n×m sparse allocation matrix W, W[i,j] = 1 if EF j is served by the NF at site i.

Example

      4  7  8  8  2  0]

Continuous Location

Logjam.ala — Function
ala(X0, w, P; dist=:mi, unit, alloc=<default>, locate=<default>, nruns=1, verbose=true, rng=nothing) -> (X, TC, W)
ala(X0, alloc::Function, P; dist=:mi, unit, locate, nruns, verbose, rng) -> (X, TC, W)
ala(n::Integer, w, P; nruns, rng, ...) -> (X, TC, W)
ala(x::AbstractVector, w, P; ...) -> (X, TC, W)

Alternating location–allocation: locate n new facilities (NFs) to serve m weighted existing facilities (EFs).

Three more call forms (A7), each the first form on other arguments:

  • ala(X0, alloc, P): a caller's allocate function in the place of w, as Matlog's ala(X0, alloc_h, P, p); it is ala(X0, w, P; alloc), whose w the default allocate alone reads.
  • ala(n, w, P): n NFs from a random start, ala(randX(P, n; rng), w, P; rng), so the generator (or, with none, the global stream) draws the start and then the restarts and the repair, exactly as the course's ala(randX(P, n), w, P) does after the same seed.
  • ala(x, w, P): one NF from the point x, a vector, as ala(reshape(x, 1, :), w, P); a vector is one point here, as in dists (S15).

ala(n, alloc, P) and ala(x, alloc, P) combine them.

Starting from n NF locations X0, alternate two steps until the total cost TC stops decreasing: allocate each EF to its nearest NF, then locate each NF at the continuous minisum of its allocated EFs. An NF that no EF is nearest to (an orphan) is moved to a random EF and the EFs are re-allocated, so every NF returned serves some EF (Matlog's default_alloc). The returned TC and W are always those of the returned X.

Formulation

Given EFs $P = \{P_j\}_{j=1}^m$, weights $w_j \ge 0$, and $n$ NFs, choose NF locations $X = \{X_i\}_{i=1}^n \subset \mathbb{R}^2$ and allocation $W \in \{0,1\}^{n \times m}$ to minimise

\[\min_{X,\,W}\; TC = \sum_{j=1}^{m} w_j\, d\!\left(X_{\sigma(j)}, P_j\right), \qquad \sigma(j) = \arg\min_i d(X_i, P_j),\]

alternating

  • allocate: $\sigma(j) = \arg\min_i d(X_i, P_j)$ (nearest NF);
  • locate: $X_i \leftarrow \arg\min_{X} \sum_{j:\sigma(j)=i} w_j\, d(X, P_j)$ (per-NF minisum),

iterating until $TC$ is non-decreasing. If $\{j : \sigma(j) = i\} = \varnothing$ for some $i$, $X_i$ is relocated to a random $P_j$ and the EFs are re-allocated, until every NF is used. The distance $d$ defaults to the great-circle distance $d_{gc}$ (dist=:mi). With nruns random starts, the minimum-TC result is returned.

Arguments

  • X0: n×2 matrix of initial NF locations (LON, LAT).
  • w: length-m weight vector (w_j ≥ 0).
  • P: m×2 matrix of EF locations (LON, LAT).
  • dist: distance metric — :mi (default), :km, :rad (great-circle), or 1/2/Inf (rectilinear/Euclidean/Chebyshev), or any real p ≥ 1 (the lₚ metric, as dists computes it; v0.3.1, A5): what dists accepts.
  • unit: a synonym for dist when it is a great-circle unit, as in dists (S15); passing both is an error.
  • alloc: allocate handle X -> (W, TC) overriding the default nearest-NF allocation (e.g. for forced/constrained partitions).
  • locate: locate handle (W, X) -> X overriding the default per-NF minisum.
  • nruns: number of independent restarts. Run 1 uses X0; runs 2…nruns use fresh randX(P, n) starts. The best (minimum-TC) result is returned.
  • verbose: print the cost trace (default: true); see below.
  • rng: a random-number generator (any AbstractRNG) for the restarts and the orphan repair, as in rng = Xoshiro(1). The default, nothing, draws from the global stream exactly as v0.2.8 did, so Random.seed!(s) before the call reproduces the same run; a generator passed here leaves the global stream untouched. The keyword is typed Union{Nothing,AbstractRNG}, so any other value is a TypeError at the call (LOC8).

A caller's own handle is never second-guessed. The orphan repair belongs to the default allocate step, so it is skipped when alloc is given (a forced partition may leave an NF empty on purpose) and when locate is given (a locate handle may hold an NF fixed, as in HW 1's fixed facility, and the repair would otherwise move it).

Trace

With verbose = true, every allocate and every locate step prints the total cost after the step, in the format of ufl's trace: Alloc after allocating, Locate after locating (the allocation held, the NFs moved), and, when nruns > 1, a k: TC = ... line closing each run and a Final: TC = ... line with the best. With a caller's alloc the Locate lines are omitted, since only that handle can cost an allocation.

Returns

  • (X, TC, W): n×2 NF locations, total cost TC, and the n×m sparse allocation matrix W where W[i,j] is the weight NF i serves from EF j.

Example

Two NFs on the I-40 mile markers of Lecture 2.3's first location–allocation example, 1-D rectilinear distance (dist = 1), from the starts 0 and 200. Each allocate and each locate step prints its cost; the NFs settle on the markers 190 and 295, at a total cost of 1,340.

P = [50 150 190 220 270 295 420]'          # I-40 mile markers
w = collect(1:7)                           # relative demand at each
X, TC, W = ala([0.0; 200.0;;], float(w), float(P); dist = 1)
(round.(vec(X)), round(TC))

Logjam.wcentroid — Function
wcentroid(LON, LAT, w) -> (LON, LAT)
wcentroid(P::AbstractMatrix, w) -> (LON, LAT)

Weighted geographic centroid of points (LON, LAT) with weights w, corrected for longitude convergence toward the poles by a cos(lat) factor. The points may also be given as the n×2 matrix P the distance and location functions take, wcentroid(P, w) being wcentroid(P[:, 1], P[:, 2], w) (v0.3.1, A8).

Formulation

Given points $\{(\text{lon}_i, \text{lat}_i)\}_{i=1}^N$ with weights $w_i \ge 0$ and $\sum_i w_i > 0$,

\[\overline{\text{LAT}} = \frac{\sum_i w_i\,\text{lat}_i}{\sum_i w_i}, \qquad \overline{\text{LON}} = \frac{\sum_i w_i \cos(\text{lat}_i)\,\text{lon}_i} {\sum_i w_i \cos(\text{lat}_i)} .\]

The $\cos(\text{lat})$ weighting corrects for meridian convergence: a degree of longitude spans less ground distance at higher latitudes, so higher-latitude points are down-weighted in the longitude average. Domain: $\sum_i w_i > 0$ and $\text{lat} \in (-90, 90)$ so $\cos(\text{lat}) > 0$.

Arguments

  • LON: vector of longitudes (degrees).
  • LAT: vector of latitudes (degrees, in $(-90, 90)$).
  • P: in place of LON and LAT, an n×2 matrix of points (LON, LAT).
  • w: vector of nonnegative weights with $\sum_i w_i > 0$.

Returns

  • (LON = ..., LAT = ...): the weighted centroid as a NamedTuple, longitude first (matching Logjam's LON–LAT order). Destructures as lon, lat = wcentroid(...) and composes directly with combine(groupby(...), ... => wcentroid => [:LON, :LAT]).

Example

Population-weighted centroid of four NC cities (rounded for a stable, cross-platform doctest — the raw Float64s carry full precision):

Logjam.binpack — Function
Logjam.binpack(v, V; tlim = 60.0, gap = 1e-4) -> (bins, used, status, gap, secs)

The fewest bins of capacity V that hold objects of sizes v, by Lecture 2.7's bin packing model (@mdl-binpack): a binary y[i], one if bin i is used, and x[i, j], one if object j is in bin i, with one potential bin for each object; minimize the bins used, $\sum_i y_i$, subject to (a) capacity, $V y_i \ge \sum_j v_j x_{ij}$, the objects in a bin within its capacity, and (b) assignment, $\sum_i x_{ij} = 1$, every object in exactly one bin. HiGHS solves it silently.

Needs JuMP and HiGHS: using JuMP, HiGHS loads the optimization extension that adds the method. Called without them, it is a MethodError that says what to load.

Arguments

  • v: the size of each object, in the bin's own unit.
  • V: the capacity of one bin. No object may be larger (the model's assumption (b)); one that is is an ArgumentError.
  • tlim: the seconds after which HiGHS gives up and returns the best packing it has found (set_time_limit_sec). The model has $m^2 + m$ binaries for m objects, and the default of 60 is Lecture 2.7's, measured to cover two hundred objects several times over.
  • gap: the relative gap at which HiGHS stops (mip_rel_gap). The objective counts bins, so a gap below one bin's share of the count changes nothing, and above it the saving comes in whole bins (Lecture 2.7).

Returns

A NamedTuple (; bins, used, status, gap, secs), Lecture 2.7's:

  • bins: for each bin used, in the order of the bins, the objects in it.
  • used: the number of bins used, the objective value as an Int.
  • status: termination_status: OPTIMAL when the search ended within gap, TIME_LIMIT when tlim ran out first.
  • gap: relative_gap, what the search achieved.
  • secs: solve_time, HiGHS's seconds.

Example

Lecture 2.7's Ex. 8, twenty objects of whole sizes from 1 to 5 (drawn there with Random.seed!(1244), written out here) into bins of capacity 10. The total is 60, so no packing uses fewer than 6 bins, and the model finds 6, each exactly full. (Shown, not run when the manual is built: the manual's environment does not load JuMP and HiGHS.)

julia> packed = Logjam.binpack(vB, 10);

julia> packed.used, packed.status
(6, OPTIMAL)

julia> [sum(vB[b]) for b in packed.bins]          # the volume in each bin
6-element Vector{Int64}:

Logjam.aggshmt — Function
aggshmt(df::DataFrame) -> NamedTuple

Aggregate multiple shipments into a single equivalent shipment.

Follows Matlog aggshmt.m (Note 3): the aggregate copies the first shipment (df[1, :]), then recomputes the aggregable fields — f (sum of demand), s (total-weight / total-volume harmonic-style mean), and v/h/a (demand-weighted arithmetic means). Every other field — including the distance d and any routing fields — is passed through unchanged from the first shipment, because aggregated shipments share one lane (no distance average). The output is therefore a complete sh row that chains directly into maxpayld/minTLC with no intervening combine.

The result also carries avh, the aggregate's inventory coefficient Σ fᵢ aᵢ vᵢ hᵢ / Σ fᵢ (the demand-weighted mean of each product's own a·v·h), always present when the table has a, v and h (CR 14). totlogcost and minTLC use it in place of the product of the separately averaged a, v and h, which is wrong when those differ across the products (Matlog's aggshmt and the ISE 453 sheets average them separately; this is a recorded departure). When h and a are alike across the shipments, or v is, the two agree. avh is computed from the rows aggregated: a hand-edited a, v or h in the result (merge(agg, (v = ...))) does not update it, so pass a new avh as well, or drop the field with Base.structdiff(agg, (avh = 0,)). Logjam.minTLC — Function
minTLC(sh; tr = nothing, ppi_ltl = nothing) -> NamedTuple
minTLC(sh, tr, ppi_ltl) -> NamedTuple

Independent shipment size that minimises total logistics cost (TLC), checking TL only, LTL only, or both modes depending on which arguments are provided. The carrier and the LTL index are given by keyword (tr, ppi_ltl) or positionally, as in minTLC(sh, tr, ppi_ltl).

The positional form is kept and unchanged (about 40 course calls write it; this note is its whole deprecation): its third argument is the LTL PPI, while tr.ppi is the TL PPI, and the keyword form says which is which. Giving the same argument both ways is an ArgumentError.

Call modes

  • TL-only (minTLC(sh, tr) or minTLC(sh; tr)): Optimises over TL shipment size using the closed-form EOQ expression; no LTL index.
  • LTL-only (minTLC(sh, nothing, ppi) or minTLC(sh; ppi_ltl)): Optimises over LTL shipment size using Optim.jl one-dimensional minimisation; no carrier.
  • Both (minTLC(sh, tr, ppi) or minTLC(sh; tr, ppi_ltl)): Computes both optimal sizes and returns the mode with the lower TLC; isLTL = true iff LTL is selected.
  • Degenerate (minTLC(sh) — neither provided): Returns (qᵒ=nothing, TLCᵒ=Inf, isLTL=false).
  • Zero distance (sh.d within 1e-4 mi of 0, Matlog's zero tolerance, with tr or ppi given): nothing is shipped, so the result is (qᵒ=0.0, TLCᵒ=0.0, isLTL=false) in every call mode (CR 15, TRN3; v0.2.8 sized the shipment by the TL minimum charge, and before TRN3 a distance such as the 9e-9 mi an optimizer leaves between a facility and its supplier was sized by it too).

Arguments

  • sh: Per-shipment parameters; a NamedTuple or DataFrameRow with fields f (demand, ton/yr), s (density, lb/ft³), a (inventory fraction), v (unit value, $/ton), h (holding rate, 1/yr), d (distance, mi). A row with an avh field (an aggshmt result) is sized and costed with avh in place of a·v·h (CR 14).

  • ppi_ltl: LTL Producer Price Index scalar (the third positional argument). Pass nothing (or leave out) for TL-only mode.

Returns

NamedTuple with fields:

  • qᵒ: Optimal shipment size (ton); nothing in the degenerate case.
  • TLCᵒ: Minimum total logistics cost ($/yr); Inf in the degenerate case.
  • isLTL: true if LTL is selected, false if TL is selected (or degenerate).

LTL search bounds

The Optim search for the LTL optimal q uses hard-coded bounds:

  • Lower: 150/2000 ton (150 lb, the LTL minimum shipment weight).
  • Upper: qmax_ltl(sh.s) = min(5, 650·sh.s/2000) ton — the smaller of the LTL weight ceiling (5 ton = 10,000 lb) and the density-derived cube-out limit (650 ft³ × density converted to tons), following the ISE 754 lecture convention.

Bracket guard. For a density below 150/650 ≈ 0.231 lb/ft³ the upper bound is below the lower one: no LTL shipment is possible, and the LTL option is left out as if ppi_ltl were not given (Matlog does the same), where v0.2.8 stopped with an error from the optimizer.

Beyond the LTL estimate's range

rate_ltl is Inf beyond 3,354 mi, so no LTL size has a finite cost there and no LTL option exists: the call does not warn or throw. LTL-only returns (qᵒ=nothing, TLCᵒ=Inf, isLTL=false) and the both-modes call returns the TL result. Check sh.d <= 3354 first where it matters.

The sh and tr contract

The fields of a shipment sh and a truck tr, shared by the transport and the routing functions, are the docstring of Logjam.shtr, so ?Logjam.shtr shows them at the REPL:

Logjam.shtr — Constant
Logjam.shtr

The sh and tr contract: the fields of a shipment sh and of a truck tr, which the transport and the routing functions share. The value lists the fields of each, shtr.sh and shtr.tr; this docstring is the contract, and ?Logjam.shtr shows it.

sh is one shipment, a NamedTuple or a DataFrameRow, or a table of shipments, a DataFrame with one row for each shipment; tr is one truck, a NamedTuple (or a DataFrameRow). They are one abstraction across the two modules: a routing sh may carry only b and e, a transport sh the economic fields, and a row with all of them works in both, because each function reads only its own fields (the cross-regime test I5). The fields both modules read (Kwt, Kcu, s, d) are the same quantities in both, so sh and tr are not renamed by module.

Row, column or table

  • A function of one shipment takes sh as a row: charge_tl(q, sh, tr), charge_ltl(q, sh), rate_ltl(q, sh), maxpayld(sh, tr), totlogcost(q, c, sh) and minTLC(sh, tr, ppi_ltl), each of which also takes the fields as scalars. Two of them also take the table, or its column, with one result for each row: maxpayld(sh, tr), or maxpayld(sh.s, tr) on the densities alone, returns the vector of maximum payloads, and minTLC(sh, tr, ppi_ltl) returns the table with qᵒ, TLCᵒ and isLTL added. charge_tl(d, tr) and mincharge_tl(tr) take the truck alone.

Read when present

A field a function reads is used when sh or tr has it. An absent field takes the default the function documents, the scalar method's or Matlog's: a tr without Kwt, Kcu or maxTC is an uncapacitated truck to rteTC, which then returns the sum of the segment costs, and charge_tl(d, tr) derives r from ppi as the scalar charge_tl does. A field with no default is required, and its absence is an error from the function that reads it. A field a function does not read is ignored, so one row or table passes through the transport and the routing calls without projection. Each method's docstring names the fields it reads.

Logjam.dgca — Function
dgca(X, Xa, a; unit=:mi, method=:max) -> Matrix{Float64}
dgca(x, Xa, a; unit=:mi, method=:max) -> Vector{Float64}

Area-adjusted great-circle distance matrix between new-facility/point set X and demand-point set Xa, each demand point standing for a region of area aⱼ taken as a disk of the same area. With method = :max, the default, each distance is floored by the mean centroid-to-random-point distance of the disk (Lecture 2.5's @eq-da2dmax); with method = :empirical it is the empirical average distance to the disk's points (2.5's @eq-daemp). For a single point x, a vector [lon, lat], the length-m vector of its area-adjusted distances to the rows of Xa: the row dgca(reshape(x, 1, :), Xa, a) (A5), by either method.

Formulation

For points $X = \{X_i\}_{i=1}^n$ and demand points $Xa = \{Xa_j\}_{j=1}^m$ with land areas $a_j \ge 0$, radius $r_j = \sqrt{a_j/\pi}$ and $d_{ij} = d_{gc}(X_i, Xa_j)$, method = :max (Lecture 2.5's @eq-da2dmax) is

\[D^{aa}_{ij} \;=\; \max\!\left\{\, d_{gc}(X_i, Xa_j),\;\; \tfrac{2}{3}\sqrt{a_j/\pi}\,\right\}, \qquad i = 1..n,\; j = 1..m .\]

The floor $\tfrac{2}{3}\sqrt{a_j/\pi}$ is the mean distance from the centroid to a uniformly random point in a disk of area $a_j$ (radius $r_j=\sqrt{a_j/\pi}$, mean centroid distance $\tfrac{2}{3}r_j$). It represents the intra-zone travel a demand point still incurs when a facility is placed at its geographic center.

method = :empirical (Lecture 2.5's @eq-daemp, fitted by regression to simulated data; X8) is

\[D^{aa}_{ij} \;=\; \begin{cases} \dfrac{2 r_j}{3} + \dfrac{d_{ij}}{48} + \dfrac{9 d_{ij}^{2}}{20 r_j}, & d_{ij} < r_j, \\[1ex] d_{ij} + \dfrac{3 r_j^{2}}{23 d_{ij}}, & \text{otherwise}, \end{cases}\]

the average distance from $X_i$ to all the points of the disk: $\tfrac{2}{3} r_j$ at its centroid, as the floor is, and more than $d_{ij}$ outside it, where a facility still pays for the region's spread. The branch test is the MATLAB dagg.m's, $d < r$, so at $d = r$ the value is $26r/23$, a step of about 0.6% down from its limit $546r/480 = 1.1375r$ just below, which belongs to the fitted formula. Lecture 2.5 runs @eq-da2dmax, since the disk that stands for the region is the binding approximation, and gives @eq-daemp for the occasions that warrant it.

No circuity: the raw $D^{aa}$ is returned; any circuity factor is applied by the caller. Degenerate $a_j = 0$ gives floor $0$, so $D^{aa}_{ij} = d_{gc}$, by either method.

Arguments

  • X: n×2 matrix of points (LON, LAT).
  • Xa: m×2 matrix of demand points (LON, LAT).
  • a: length-m vector of demand-point areas, in the areal unit whose square root matches unit (e.g. mi² for unit=:mi).
  • unit: distance/area unit — :mi (default), :km, or :rad.
  • method: :max (default) or :empirical, as above (X8; the keyword and its values provisional, D7).

Returns

  • D: n×m matrix where D[i,j] = max(dgc(X[i,:], Xa[j,:]; unit), (2/3)√(a[j]/π)), or with method = :empirical @eq-daemp at that distance and r = √(a[j]/π).

Example

Compute distance matrix between two point sets using specified metric.

Replaces: Dgc with unified interface supporting all metrics.

Arguments

  • X1: m×n matrix of m points in n dimensions
  • x: a single point, a vector of n coordinates, in place of X1
  • X2: k×n matrix of k points in n dimensions
  • p: Distance metric (default: 2)
    • 1: Rectilinear (Manhattan, l₁) distance
    • 2: Euclidean (l₂) distance (default)
    • real p ≥ 1 (incl. Inf): general lₚ metric (Σ|Δ|ᵖ)^(1/p); Inf gives the Chebychev (l∞) distance maximum(abs, Δ); an integer p such as 3 is the same metric as 3.0 (N19)

\[d_p(x,y) = \Big(\sum_{t=1}^{n} |x_t - y_t|^{p}\Big)^{1/p}, \quad p \in [1,\infty); \qquad d_\infty(x,y) = \max_{t} |x_t - y_t| \;\text{(Chebychev)} .\]

Logjam.thin — Function
thin(dfN::AbstractDataFrame, dfL::AbstractDataFrame) -> Tuple{DataFrame, DataFrame}

Thin a road network: remove its degree-2 nodes, replacing the two arcs at each with one whose cost is their sum, and where that leaves two arcs between the same nodes in the same direction keep the one of minimum cost (Lecture 4.1, Sec. 4, "Thin"; Matlog's thin). The procedure repeats until no node can be removed, so a chain of any length becomes one link and a loop such as a beltway between two junctions is eliminated.

A node is removed when its neighbors are two other nodes and it is passed through in every direction it is used: two-way (an arc each way to each neighbor), or one-way (one arc in from one neighbor and one out to the other). So a one-way chain is merged as a one-way chain, and a network with one link per direction of travel, as OpenStreetMap's, keeps both of its directions (CR 25). Links are read as arcs by DIR (0 two-way, 1 from SRC to DST, -1 from DST to SRC); a network with no DIR column is two-way. The result does not depend on how the nodes are numbered: the nodes are visited in the order of the rows of dfN (CR 18).

Columns are read by position: the first column of dfN is the node ID, and the first three of dfL are the source, the destination and the distance.

Arguments

  • dfN: Nodes DataFrame with columns [IDX, LON, LAT, ...]. The IDs are integers, in any order.
  • dfL: Links DataFrame with columns [SRC, DST, DIST, ...].

Returns

  • (N, L), the thinned nodes and links, whatever the input (the number of values returned never changes): N holds the nodes that remain on a link and L the links. The nodes of N are numbered 1:n in the order they had, and SRC and DST are renumbered to match (N6), so the tables are ready for links2graph, addconnectors and drawing a path by row, with no prune_reindex.
  • L has every column of dfL, and one more, MERGED: the rows of dfL that make up each link, in order along the road. The distance of a merged link is the sum of its parts; every other column, a speed or a name, is that of its first link, and DIR is 0 for a link that can be traveled both ways.

Logjam.addconnectors — Function
addconnectors(dfN::AbstractDataFrame, dfL::AbstractDataFrame,
              x_prime::AbstractVector, y_prime::AbstractVector;
              circuity::Real=1.3, add_nf_nf::Bool=false, speed=nothing,
              src_col=1, dst_col=2, dist_col=3,
              node_col=1, x_col=2, y_col=3) -> Tuple{DataFrame, DataFrame}

Add connector links from demand points to a road network.

Each new point is joined to the three network nodes at the corners of the triangle that contains it, in the Delaunay triangulation of the network's nodes (Lecture 4.1, Sec. 4, "Add connectors"), or to the two nodes of the hull edge facing it when it lies outside every triangle. The triangle is found by an exact point location that does not triangulate the whole network: the triangle of the point's 16 nearest nodes (doubling the number as needed) that contains it, accepted only when its circumcircle holds no other network node, which makes it a triangle of the whole network's triangulation. The connectors are the same as the whole triangulation gives, and the search takes the same code path at every size of network (a crop of 8,691 nodes and the 95,699-node OpenStreetMap tile of Lecture 4.2 alike). A point outside the network's hull is the one case that uses the whole triangulation.

Demand points are assigned node IDs 1:n, and existing network nodes are shifted by n (i.e., old node 1 becomes n+1).

The links' distance column must be a distance, in miles (the third column of dfL, DIST in FAF5 and OpenStreetMap): a connector's value there is the great circle distance times circuity, so a table whose third column holds minutes would mix the two. Arguments

  • dfN: Nodes DataFrame with columns [IDX, LON, LAT, ...].
  • dfL: Links DataFrame with columns [SRC, DST, DIST, ...].

  • add_nf_nf: If true, also add direct connectors between neighboring demand points, from a Delaunay triangulation of the demand points, each at circuity times the great circle distance (default false: when the road distance between two new points is wanted, a connector between them is only an estimate that can become the shortest route, as in Lecture 4.1's Code block 45 and its annotation 1; Matlog leaves the choice to the caller too).

  • src_col, dst_col, dist_col: Link columns for source, destination, and distance.
  • node_col, x_col, y_col: Node columns for node ID, longitude, and latitude.

Returns

  • Tuple of (newnodes, newlinks) DataFrames with connectors added.

Logjam.joinroads — Function
joinroads(N, L, Nosm, Losm, bb; radius = 0.5, verbose = false) -> (dfN, dfL)

The U.S. road network with an OpenStreetMap network joined in, for routes that start or end on a city's streets and run far beyond them: inside the box bb the OpenStreetMap streets replace the national roads, outside it the national roads stay, and each national road that crosses the box edge is joined to the streets by a connector at the edge. N and L are the national network as usrdnode and usrdlink return it (with any of their keywords), Nosm and Losm the OpenStreetMap network as osm_roads(bb) returns it, and bb is the box given to osm_roads; none of the five is changed.

  1. Inside the box, every national node goes, and with it every national link with an end inside or whose straight line crosses the box.
  2. Each national link that crossed the box edge is joined, at its end outside the box, by a connector to the OpenStreetMap node nearest the point where the link met the edge, on a road of the same or an adjacent class (the table below) that continues the link's direction of travel. When no such node lies within radius miles of that point, the connector goes to the nearest node on a road of any class that continues it, and is counted (verbose).
  3. The national links left, the OpenStreetMap links and the connectors are stacked and renumbered with prune_reindex, so the nodes are numbered from 1 and the network is ready for links2graph.

Arguments

  • N, L: the national network: nodes with IDX, LON, LAT; links with osm_roads' first eight columns (SRC, DST, DIST, SPEED, FCLASS, DIR, NAME, SOURCE), which usrdlink has.
  • Nosm, Losm: the OpenStreetMap network, the same columns.
  • bb: the box inside which the OpenStreetMap streets replace the national roads, the box given to osm_roads: ((xmin, xmax), (ymin, ymax)) as mapbbox returns it, or the four numbers (xmin, xmax, ymin, ymax). The OpenStreetMap network is cropped to it too, so that no road of either network lies where the other has one, and a whole tile read without crop joins as it does cropped to bb.

Keywords

  • radius = 0.5: miles, around the point where a national link meets the box edge, within which a node of an adjacent class is looked for.
  • verbose = false: with true, report the national links and nodes dropped, the connectors made and how many of them went to a road of a class that is not adjacent.

Connectors

A connector runs from the national link's node outside the box (SRC) to the OpenStreetMap node (DST). Its DIST is the great circle distance between them (dgc), its SPEED the slower of the two roads' speeds, its FCLASS and NAME the national road's, since it stands for the part of that road the box cut off, and its SOURCE is "CONNECTOR". It goes each way the national link can be traveled, to a node from which the OpenStreetMap road goes on that way: into the box, a node with a link of an accepted class leading on, away from the national road; out of the box, a node that such a link reaches from farther away. One node usually serves both ways, and the connector is two-way (DIR = 0). Where the OpenStreetMap road is divided, so that each carriageway is one-way, the two ways are two connectors, each one-way (DIR = 1 into the box, -1 out of it) to the carriageway of its direction, since a two-way connector to one carriageway would lead against it. A one-way national link has its one connector.

Returns

  • dfN: nodes IDX (1 to n), LON, LAT, SOURCE ("FAF5" and "OSM"), the national nodes first.
  • dfL: links with osm_roads' first eight columns, in its order, so vcat with an osm_roads table works; SOURCE is "FAF5", "OSM" or "CONNECTOR". The national network's other columns follow (SIGN, TYPE, INTERSTATE, AB_TIME, BA_TIME, STFIP, COFIP, URBAN from usrdlink), missing on the OpenStreetMap links and the connectors, and then any of the OpenStreetMap network's own (MAXSPEED, ACCESS, CONDITIONAL from a download), missing on the others. Since AB_TIME and BA_TIME are missing there, links2graph(dfL; weight = :time) times an OpenStreetMap link and a connector at 60 * DIST / SPEED and a national link by its own times.

Logjam.rteTC — Function
rteTC(rte, sh, C, tr = (;); full = false) -> Float64

The total cost of a route, Matlog's rteTC ported whole: the sum of the costs between the stops of the route's location sequence, with the truck's capacity, a maximum cost and, when asked for, loading and unloading times and time windows checked. A vector of routes R (a vector of vectors) is costed route by route.

With full = false, the default, it returns the cost alone, Inf for a route that breaks a limit the truck carries (see Notes). With full = true it returns the named tuple (TC, Xflg, out), which destructures as TC, Xflg, out = rteTC(...; full = true): the cost, an exit flag naming the constraint a route violates, and a table of the route's stops. The cost handle savings and twoopt take is rte -> rteTC(rte, sh, C, tr); for a schedule it is rte -> rteTC(rte, sh, C, tr; full = true).TC.

Arguments

  • rte: Route, a vector of shipment indices (first appearance a loading, second an unloading).
  • sh: Shipments table. Columns b, e (locations, required). Optional columns: q (weight, tons) and s (density, lb/ft³; with Kcu) for capacity; with full = true also tL, tU (time to load, to unload) added to the route's time, and tbmin, tbmax (earliest and latest time a loading begins) and temin, temax (earliest and latest time an unloading ends), the shipment's time windows.
  • C: Matrix of costs or times between locations. The cost between two stops at the same location is 0 whatever C[i, i] is, as Matlog's ("costs C(i,i) ignored").
  • tr: Truck, a named tuple, every field optional: b, e (the truck's begin and end locations, put at the route's ends); Kwt (tons), Kcu (ft³) capacities, checked on each load mix; maxTC, the maximum total cost of a route; with full = true tbmin, tbmax, temin, temax, the truck's windows (at its b and its e, and at the stops at them).
  • full: (keyword) false the cost alone; true the cost, flag and table.

Returns

  • TC: the total cost: the costs between stops plus, with full = true, the loading and unloading times, added in order from the left; with time windows (full = true), the route's least time, its waiting included (scanTW); Inf for an infeasible route.
  • Xflg: 1 feasible; -1 a depot route (tr.b == tr.e) that returns to its depot midway, which is more than one route (Matlog's degenerate location vector); -2 weight over tr.Kwt at some load mix; -3 cube over tr.Kcu at some load mix (2000 ∑ q/s, with a rounding tolerance of 0.01√eps(), so a load of exactly maxpayld is not over); -4 the cost over tr.maxTC, which is tested on travel plus loading and unloading before the time-window scans, so it does not bound a windowed route's duration; -5 a time window cannot be met.
  • out: a DataFrame with one row per stop (the truck's first and last included, given tr.b), empty for an infeasible route. Columns Rte (the route, 0 at the truck's ends), Loc (locations), Cost (travel time into each stop, 0 for the first and for a stop at the previous location) and, if any tL or tU is given, LU. With a window (any of the four fields, on sh or on tr) it holds the schedule: Arrive, Wait, TWmin, Start, LU, Depart, TWmax, Total (travel + wait + loading and unloading). Logjam.scanTW — Function
Logjam.scanTW(t, u, ℓ, h) -> (TC, a, b, c)

The three scans that find a route's least time within its time windows, Lecture 5.3's implementation of the time-window scan (slide 254's rows a, b, c); rteTC(...; full = true) calls it for a route with time windows.

For the stops k = 1, ..., n of a location sequence (the first and last the truck's location): t[k] is the travel time into stop k (t[1] = 0), u[k] the loading or unloading time there, ℓ[k] the opening and h[k] the closing of its window (-Inf and Inf for none).

Logjam.mincostinsert — Function

Insert a shipment into a route at the minimum cost position.

For pickup-delivery problems, both the pickup and delivery must be inserted. This function tries every position at which the result is a route, that is, a vector on which a shipment is on board over every segment, and returns the best. For a route of m stops the loops are i = 1:m for the pickup and j = max(2, i):m + 1 for the delivery: m(m + 3)/2 - 1 positions, the count of Lecture 5.2's Eq. insert-count. Logjam.savings — Function
savings(rteTCh, sh; TC1 = nothing, ijs = pairwisesavings(rteTCh, sh; TC1)) -> Vector{Vector{Int}}

Construct routes for a Pickup and Delivery Problem (PDP) by the savings procedure of Matlog's savings.m: the pairs of the savings list, largest saving first, are taken in turn, and a pair joins routes only if the joined route costs less than the routes it replaces.

Unlike the standard Clarke-Wright algorithm (which concatenates routes at endpoints), a route is joined to another by inserting its shipments, one at a time in the order they are loaded, into the cheapest positions of the other with mincostinsert. For a pair (i, j) there are Matlog's three cases:

  1. Neither shipment is on a route: the shipments form a new route (the shorter of the two single-shipment routes is inserted into the longer; of equal length, into the costlier), kept if c(i) + c(j) - c(route) > 0, where c(k) is the cost of shipment k on a route of its own.
  2. One is on a route: the other is inserted into it, kept if c(k) + c(route) - c(new route) > 0. A shipment already tried against a route that has not changed since is not tried again.
  3. Both are on different routes: the shorter route is inserted into the longer, kept if the costs of the two routes exceed the cost of the combined one.

A merge is never made unless it saves (CR 39): v0.2.8 accepted a merge on the pair's saving alone and could return routes that cost more than shipping each shipment by itself. The list is passed over again until a pass makes no change or every shipment is on a route.

Arguments

  • rteTCh: Function that calculates route cost: rteTCh(route) -> cost. Should return Inf for infeasible routes (capacity, time windows, etc.); an insertion with no finite position is not made.
  • sh: Shipments DataFrame where each row is a shipment requiring pickup and delivery.
  • TC1: (keyword) the independent total cost of each shipment, a vector with one element per shipment, as in pairwisesavings. It is the cost the default savings list is made with and the c(k) of the merge tests above, so that a savings list and the merges it drives rank and accept on one cost. Matlog's savings.m has no such argument and tests each merge against rteTCh([k, k]), whatever cost its list was made with. The default, nothing, is rteTCh([k, k]) for shipment k in both, and an unchanged call is unchanged.
  • ijs: (keyword) the savings list, taken in the order given: the named tuple (i, j, s) that pairwisesavings returns (only the first two vectors are read; a plain tuple also works), or an m x 3 matrix with a pair in each row, Matlog's IJS. The default is pairwisesavings(rteTCh, sh), the pairs of positive saving, largest first. A list of your own is how the savings are changed before the routes are built, as Lecture 5.2's randomized savings does with its own randreorder (Matlog's randreorder; makeRouting2.m lines 148-153: twoopt(savings(rTDh, sh, randreorder(IJS, 0.1)))). A list with no pair gives no route.

Returns

  • Vector of the routes formed, each a vector of shipment indices, in the order they were formed; as in Matlog, only the routes the procedure makes. A shipment that no pair of the list joined to a route is on none of them, and is shipped on a route of its own, [k, k], which the caller adds (Matlog's sh2rte; Lecture 5.2's sh2rte(1:n, R)). With v0.2.8's savings every shipment came back on a route, those in no saving as a single-shipment route among the routes formed (CR 57), so the index of a route said nothing about whether savings had formed it. No shipment is on more than one route.

Logjam.twoopt — Function
twoopt(r, rTCh; verbose = false) -> (rte = improved route or tour, TC = its cost)

Improve a tour or a route with the first-improvement 2-opt procedure.

The procedure reverses a stretch of the vector, keeps the change if the total cost falls, and starts the scan again from the new vector; it stops when a whole scan improves nothing. twoopt runs one of two neighborhoods, and which one is decided by the vector itself:

  • A route vector is one in which every element appears exactly twice, the first appearance a shipment's pickup and the second its delivery (the form rteTC, rte2loc and mincostinsert take). Its neighborhood is Matlog's twoopt.m: i = 1:m - 1, j = i + 1:m over the m stops, reversing r[i:j], so the first and last stops can move, and a reversal that leaves the truck empty between two shipments is never considered, since such a vector is two routes and not one (as in Lecture 5.2's loops). The result is a route whenever the start is one. As in Matlog and in Lecture 5.2's twoopt_rte, a reversal is kept if its cost is strictly lower, so a change that is zero in exact arithmetic (all the deliveries of a depot route reversed) is kept or not by the 1e-13 rounding of the machine's order of summation; where such a tie arises, the route a run ends at can differ between computers, as it does for the lecture's own function.
  • Anything else is a tour, a location sequence that returns to its first element (r[1] == r[end]), as in Lecture 5.1. Its neighborhood is the closed tour's: the first and last elements stay in place and r[i+1:j] is reversed for i = 1:m - 2, j = i + 2:min(m - 1, m + i - 3). A tour is not a route vector, because a tour visits each location once and the depot twice, so no tour has every element twice except the degenerate [a, a], on which neither neighborhood has a move.

Arguments

  • r: Initial route vector or tour.
  • rTCh: Function that calculates the total cost of a whole vector: rTCh(r) -> cost. It may return Inf for a vector that violates a constraint; it need not be a sum of arc costs.
  • verbose: (keyword) true prints each vector the procedure considers with its cost, as Lecture 5.1's twoopt_prt (Code block 15) prints them: first the start, "*" TC ": " r; then, in the order considered, " " TC ": " r′ for a change that is not kept and "*" TC ": " r′ for one that is, so the starred lines are the vectors the search moves through. Each line's cost is the one rTCh returned for its vector, and each line is printed with println. A route's reversal that leaves the truck empty is not considered, so it is not printed. Default false, which prints nothing.

Returns

  • The named tuple (rte, TC), the improved vector and its total cost, which destructures as r, TC = twoopt(r, rTCh). The input is not modified.

The TSP as a MILP

Lecture 5.1's formulation of the traveling salesman problem, solved one round of subtour constraints at a time. TSP needs the optimization extension (using JuMP, HiGHS), so the manual shows its example without running it; subtours needs nothing.

Logjam.TSP — Function
Logjam.TSP(c) -> (TC, tour, rounds)

The optimal tour of a traveling salesman problem (TSP) on the arc costs c, by Lecture 5.1's math-programming formulation (@mdl-tsp, the DFJ formulation): a binary x[i, j] for each arc i ≠ j, one if the tour goes from node i directly to node j; minimize $\sum_{i,j} c_{ij} x_{ij}$ subject to (a) each node left once, (b) each node entered once, and (c), single tour, $\sum_{i \in S} \sum_{j \in S} x_{ij} \le |S| - 1$ for each subset $S$ of the nodes, neither empty nor all of them.

Row (c) has one constraint for each subset, so the formulation is solved one round at a time (constraint generation): rows (a) and (b) alone, the assignment problem, are solved first; Logjam.subtours finds the cycles of the solution; row (c) is added for each of them, and the problem is solved again, until the solution is a single tour. Each round solves the TSP with only some of its subtour constraints, so its cost is a lower bound on the optimal tour's and the costs can only rise from round to round; the tour of the last round satisfies every subtour constraint without their having been added, so it is optimal.

Needs JuMP and HiGHS: using JuMP, HiGHS loads the optimization extension that adds the method. Called without them, it is a MethodError that says what to load. HiGHS solves each round silently with mip_rel_gap = 0, so the tour is proved optimal rather than within HiGHS's default gap of 0.01%.

Arguments

  • c: square matrix of arc costs, c[i, j] the cost from node i to node j, for n ≥ 2 nodes; symmetric or not. The diagonal is not read.

Returns

A NamedTuple (; TC, tour, rounds):

  • TC: the optimal tour's cost, HiGHS's objective value (Float64).
  • tour: the optimal tour as a location sequence, starting and ending at node 1.
  • rounds: one (; TC, S) for each round, in order: the round's cost and its cycles, Logjam.subtours of its solution. The last round's S is the tour, as a single cycle.

Throws an ArgumentError for a matrix that is not square or has fewer than two nodes, and an ErrorException naming HiGHS's termination status when a round does not end OPTIMAL.

Example

Logjam.loc2lonlat — Function
loc2lonlat(s::AbstractString; state=nothing, cache=nothing, force_download=false)

Geocode a single location string. Accepts addresses, city names, postal codes.

Returns a named tuple (LON, LAT, GC_SOURCE, GC_UNCERT, GC_STATUS): the same field names as the columns the vector and DataFrame methods return (R7/S14). At v0.2.8 the scalar method's metadata fields were lowercase source, uncert and status; LON and LAT never changed. The names used below, source, uncert and status, are these fields without the GC_ prefix.

Address strings

A string with a comma or a digit is read as an address, from the end: an optional five-digit ZIP (or ZIP+4), then an optional state (a spelled-out name or a two-letter code, as a whole word), then the city and street, split at the last comma. "10420 Falls of Neuse Rd, Raleigh, NC 27614" is street 10420 Falls of Neuse Rd, city Raleigh, state NC, ZIP 27614; "Atlanta, Georgia" is Atlanta, GA. A state keyword is never overridden by what the text says: where the two disagree the keyword is used, with a warning.

Plain names and postal codes

A string with no comma and no digit is read as a city, and a five-digit string as a postal code, and each enters the same tier ladder as an address string (GC), so a name that is not found falls back to its state: loc2lonlat("Raliegh"; state = :NC) answers at the STATE tier with status PARTIAL, as loc2lonlat("Raliegh, NC") does (Lecture 4.2's Code block 1 geocodes that one). With no state, a name or ZIP that is not found is FAIL, and so is a name that matches several places.

Source and status

source is the tier that answered: ADDRESS (Nominatim, house number found, uncert = 0), STREET (Nominatim found the street but not the house number, status PARTIAL, uncert missing: no house number is invented), PLACE, POSTALCODE, COUNTY or STATE (the census tables). status is OK for an exact answer at the tier the input asked for, PARTIAL for a coarser one, FAIL for none. When an address with a street is answered by a lower tier, a warning names the input, why the address tier did not answer (not found, not loaded, or a failed query) and the tier used, so a city centroid is never returned silently. In a vector or DataFrame call a state that is not a state makes that row FAIL (with a warning) instead of stopping the call.

Uncertainty, and the three ways an area becomes a distance (N25)

uncert is in miles. An exact address has 0. A place, ZIP, county or state centroid has (2/3)·√(a/π) for its land area a in mi² (R2/S3): the mean distance from the centroid to a uniformly random point of a disk of that area (radius r = √(a/π), mean distance 2r/3), the same constant that floors dgca. Two other conversions in the package differ on purpose: lonlat2loc calls a point "in" a place within the full radius √(a/π) of its centroid (the boundary of the equal-area disk, not the mean distance to it), and the STATE tier is the plain population-weighted mean of the county centroids' longitudes and latitudes, not wcentroid's cosine-latitude weighting, with a the sum of the counties' land areas. v0.2.8's uncert was 0.45·√a, a constant with no stated basis, 1.2 times larger.

Cache

Only street addresses sent to Nominatim (the ADDRESS and STREET tiers, which need using HTTP, JSON3) are cached, with the queries it could not answer (stored as NOTFOUND, so the same bad query is not sent twice, as Nominatim's usage policy asks); place, postal-code, county and state lookups read the built-in tables and need no cache.

  • cache = nothing (default): results are kept for this call only; no file is read or written.
  • cache = "path/to/geocode_cache.csv": entries already in that file are reused, and addresses resolved by this call are appended to it when the call ends. The file (and its folder) is created on the first entry; a call that adds nothing leaves it untouched.
  • force_download = true queries Nominatim even for an address already in the cache (the new result is appended and supersedes the old one).
  • cache_dir = dir is deprecated: it means cache = joinpath(dir, "geocode_cache.csv").

Examples

loc2lonlat("27601")                # => (LON, LAT, GC_SOURCE="POSTALCODE", GC_UNCERT, GC_STATUS="OK")
loc2lonlat("123 Main St, Raleigh, NC 27601")  # ADDRESS tier via Nominatim (needs HTTP+JSON3;

# => same result; the address is stored in data/geocode_cache.csv, so a re-run sends no query

U.S. Road Network

Logjam's U.S. road network is derived from FAF5 and differs from it in that each stretch of road between two junctions is one link, the two carriageways of a divided road one two-way link, each interchange and divided-highway intersection one node with its ramps gone, and each link carries an Interstate flag, so the Interstates are a subset of it.

Logjam.usrdlink — Function
usrdlink(; interstate = false, fclass = nothing, region = nothing) -> DataFrame

Returns the links of Logjam's U.S. road network, derived from FAF5 (faf5nodes, faf5links, which stay as FAF5 publishes them) for long-distance routing and map backgrounds. Each stretch of road between two junctions is one link; the two carriageways of a divided road are one two-way link, and a road that is genuinely one-way stays one-way; each interchange and each divided-highway intersection is one node, and its ramps are gone; the nodes along each road are kept, so it follows the road's course. The network is made by tools/v0_3_1/make_faf5net.jl and ships as a lazy artifact, downloaded on first use. The file is read once per session and each call returns a copy, so the table may be changed freely.

Keywords

  • interstate: true keeps only the Interstate links (INTERSTATE).
  • fclass: one functional class or a collection of them (such as 1:3) keeps only the links of those classes.
  • region: :CUS, the continental U.S. as makemap names it (CUS_LIMITS), keeps only the links with both ends inside it; nothing (default) keeps the whole network, Alaska, Hawaii and Puerto Rico included.

A link is kept when it meets every keyword given. usrdnode with the same keywords returns the nodes the kept links use, so the two tables are one network.

Columns

The first eight are osm_roads' columns, in its order, so the two tables can be stacked with vcat.

  • SRC, DST: the link's two nodes (IDX of usrdnode, FAF5's node numbers).
  • DIST: miles. A divided road's is its shorter carriageway's; a link whose end was moved to its junction's node adds the straight-line distance moved.
  • SPEED: FAF5's posted speed limit (mph).
  • FCLASS: the FHWA functional class as FAF5 gives it (1 Interstate, 2 other freeway or expressway, 3 other principal arterial, 4 minor arterial, 5 major collector, 6 minor collector, 7 local), the lower of a divided road's two carriageways. FAF5 also writes two codes that are no FHWA class: 0, and 10 on one link (US 183 in Lampasas County, Texas).
  • DIR: 0 two-way, 1 one-way from SRC to DST, -1 one-way from DST to SRC.
  • NAME: FAF5's road name (missing where it has none).
  • SOURCE: "FAF5".
  • SIGN: the routes the road is signed as, sorted and joined by ; (missing where it has none).
  • TYPE: Matlog's road type: "I" an Interstate, "U" a U.S. route, "S" a state route, "L" a road with a name and no route, missing otherwise.
  • INTERSTATE: true for an Interstate, Business routes excepted.
  • AB_TIME, BA_TIME: free-flow minutes from SRC to DST and from DST to SRC, a divided road's from each of its carriageways; links2graph(L; weight = :time) reads them.
  • STFIP, COFIP: state and county FIPS codes.
  • URBAN: FAF5's urban area code as FAF5 gives it, its codes 99998 and 99999 included (missing where FAF5 gives none).

Sources

Derived from U.S. Department of Transportation, Bureau of Transportation Statistics, Freight Analysis Framework (FAF5) Network (see faf5links).

Requires using CairoMakie, GeoMakie. The box alone is makemap(bb); a map in a cell of a figure that exists is makemap(cell, x, y) (see their docstrings).

Arguments

The box of a named county or place (a city, town or census-designated place), in the form mapbbox(x, y) returns, ((xmin, xmax), (ymin, ymax)), offline. state is required, since names repeat across states: a two-letter code, a Symbol or a full name. xexpand and yexpand widen the box, a county's or a place's, as they do a box given to mapbbox.

Which box. A name that matches a county of the state gives the county's box; a name that matches no county gives the box of the place of that name. So a county comes first: "Durham" in North Carolina is Durham County, and place = true asks for the place instead, the city of Durham, even where a county has the name (MakePlan D3, X7).

A county's box is the extent of the county's Census block groups, each widened by the radius of a disk of its land area (sqrt(ALAND / π), converted to degrees of longitude and latitude at the block group's latitude), which reaches the county's edge where the block groups' points alone fall short of it. It is computed exactly as Lecture 4.2's Code block 3 computes Wake County's box, and is equal to its bbW (reordered), so osm_roads snaps it to the same tile. The county is matched by its name in uscounty, ignoring case, with or without a trailing "County".

A place's box is the extent of the place's Census 2020 polygon, the bounding box the U.S. Census Bureau's TIGER/Line 2020 place shapefile records for it, kept in data/usplacebox.jls for every place of usplace (made by tools/v0_3_1/make_placebox.jl). It contains the place's usplace() point. The place is matched by its name as usplace() writes it, ignoring case: a city's or a town's name alone ("Raleigh"), any other place's with its designator ("Durham CDP", "Oakwood village"). Logjam.aligntext — Function
aligntext(x::Union{Real, AbstractVector{<:Real}, Tuple{Vararg{Real}}},
          y::Union{Real, AbstractVector{<:Real}, Tuple{Vararg{Real}}};
          offsetamt::Real=1, mindistratio::Real=1.5, idx=nothing) -> Pair, Pair

Determines text alignment and offset positions for given points.

This function attempts to calculate the best alignment and offset positions for text labels based on the spatial arrangement of the points provided. It is particularly useful for positioning labels or annotations on a plot, ensuring that they do not overlap and remain readable. The function can handle various input formats for the points, including scalars, vectors, and tuples, and adjusts the text position to try to avoid collisions with nearby labels or graphical elements.

Arguments

  • x: Scalar, vector, or tuple representing the x-coordinates for the points.
  • y: Scalar, vector, or tuple representing the y-coordinates for the points.
  • offsetamt: Scalar value specifying the amount of offset to apply to the text labels. This controls the distance by which the text is shifted away from the point. Default is 1.
  • mindistratio: Scalar value that sets the minimum distance ratio used to decide the best alignment for text labels relative to adjacent points. Default is 1.5.
  • idx: Optional index or index vector. When provided, alignment is computed using all points but only results for the specified indices are returned. Useful for labeling a subset of points (e.g., a depot) while considering all points for placement.

Returns

  • :align => alignout: A Pair where :align is associated with an array of 2-tuples representing horizontal and vertical alignment symbols (e.g., (:left, :bottom), (:center, :top)) corresponding to each point.
  • :offset => offsetout: A Pair where :offset is associated with an array of 2-tuples representing the x and y offsets to be applied to the text labels for each point.

Behavior

  • Single Point: If only one point is provided, the function returns a default alignment (:left, :bottom) with the specified offsetamt.
  • Two Points: If two points are provided, the function calculates the angle between the points and determines the best alignment and offset in both directions.
  • Three or More Points: For three or more points, the function uses Delaunay triangulation to determine the optimal alignment by analyzing the angles and distances between adjacent points. It ensures that labels do not overlap and are well-positioned relative to each other.

Example

A single point gets the default lower-left placement; multiple points return per-point alignment/offset vectors (the output is discrete symbols and integer offsets):

aligntext(ax, x, y, labels; fontsize, font, lineheight, justification, rotation, maxgap = 30, fix = nothing,
          prefer = :outward, verbose = false) -> Tuple of Pairs

Place labels beside the points x, y of the axis ax, clear of everything already drawn in it, and return the keyword arguments of text! that draw them there, to be splatted into it:

text!(ax, x, y; color = ink, aligntext(ax, x, y, names; fontsize = 18)...)

Requires Makie: the method is the Makie extension's, which CairoMakie loads, with or without GeoMakie. It works on a plain Axis and on the GeoAxis of makemap. Where aligntext(x, y) sees only the points, this method reads the figure as it is drawn: each label's ink at its font and size, and, in the axis's pixels, every line (at its width), every marker and every other label in the axis, and a legend inside it.

Arguments

  • ax: the axis, an Axis or a GeoAxis, with everything the labels must clear already drawn in it.
  • x, y: the points' coordinates, one per label, as text! takes them.
  • labels: the strings, one per point; a label may have several lines ("Asheville\n(L2)"), placed as one block whose lines are justified to the side away from the point.
  • fontsize, font, lineheight, justification, rotation: the keywords that set a label's size and shape. Give them here and not to text!: each one given comes back in the returned pairs, so the labels are drawn at the size they were placed at (giving one to both is Julia's repeated-keyword error). Any other keyword of text!, such as color, goes to text!.
  • maxgap: the ordinary search radius, in pixels (default 30). A label may go beyond it, to twice maxgap, only at a steep cost, and so only to clear a data line, a marker or another label; touching a base layer within maxgap is preferred to drifting farther.
  • fix: labels pinned by hand, as pairs label => (align, offset), the label named by its string or its index: fix = ["Charlotte" => ((:right, :center), (-12, 4))]. A pinned label is drawn exactly there, and the others are placed around it. align is one of (:left, :center), (:left, :bottom), (:center, :bottom), (:right, :bottom), (:right, :center), (:right, :top), (:center, :top), (:left, :top) and (:center, :center); offset is in pixels.
  • prefer: which side of its point a label prefers when several are clear. :outward (default) the side aligntext(x, y) chooses from the points' arrangement; :imhof the cartographic order northeast, northwest, southwest, southeast, east, north, west, south (Imhof; Christensen, Marks and Shieber 1995, Fig. 1); :near no side, and no cost for sitting nearer another labeled point, for labels such as a link's miles.
  • verbose: print one line per flagged label (below), naming it, its placement as the align and offset that fix takes, and what it touches. Default false, which prints nothing.

Returns

A tuple of pairs for text!: :text => labels, :align => A, :offset => O, and each of the size-setting keywords given, in the order listed above. A is a vector of (horizontal, vertical) alignments and O a vector of (dx, dy) offsets in pixels, one per label.

How a label is placed

Each label is tried at the eight sides of its point (east, northeast, north, and so on, the alignment following the side) at radii from 3 pixels out to twice maxgap. A candidate costs its distance (more steeply past 20 pixels, and again past maxgap), its side's rank under prefer, and what it touches: a data line, a marker or another label 1000 each, a base layer 40, any part outside the axis 5000; a label nearer another labeled point than its own costs 30, since it would read as that point's. The base layers are makemap's, recognized by the labels the map extension gives them ("FAF5 Roads" with the close tier's other road classes, "Major Roads", "Interstate Roads", "US State Borders", "Country Borders"); on a map, a line fainter than opacity 0.35 is the muted background and no obstacle. A label none of whose sides within maxgap is clear of everything, base layers included, then searches every offset on a 1-pixel grid within maxgap, nearest first, and is offered the first six that clear everything by 1 pixel.

Closeness to its point outweighs a base line that only grazes it. A base line crosses a label when its stroke enters the ink box of one of the label's lines, and grazes it when it touches only the 2-pixel clearance around them. A crossing costs the 40 always. A spot that grazes a base layer and touches nothing else costs the 40 if some spot clear of everything, or the spot the label would take with the full 40, is as near its point or nearer, the distance measured as it is seen, from the point to the nearest ink of the label; otherwise it costs only 1 for each segment of the layer it touches. So a label never moves farther from its point only to clear a line that grazes it, never takes a spot where a base line crosses its text to be nearer, and the rule only ever brings a label nearer; data lines, markers, other labels and the axis edge are avoided as before.

The labels then move one at a time to their best positions given the others, the move that lowers its label's cost most first, until no move lowers any; where two labels contend for a place, the one that loses less by moving gives way.

A label left touching something, or beyond maxgap, is flagged: nothing within reach was clear, or, where it touches only a base layer, nothing as near its point was. The placement is still returned; verbose = true names each flagged label, which can then be pinned with fix, the map widened, or the label shortened.

Behavior

  • Deterministic. No random number is drawn, so the same figure gives the same placement on every run, with verbose on or off.
  • Call it last, after everything the labels must clear is drawn and the figure has its final size: the placement is in the pixels of the figure as laid out, and a later resize! or plot moves what it was placed against.
  • The axis is left as it was: the labels are laid out in a temporary plot, deleted before the method returns.
  • aligntext(x, y) is unchanged and still returns only :align and :offset, from the points alone.

Examples

Logjam.prt — Function
prt(X; rows, cols, title, fracdig, allfrac, row_title, str)

Pretty-print a matrix, vector, or DataFrame with smart formatting.

Formatted display with right-aligned columns. Each column is formatted from its own values, by the per-column digit rule of MATLOG's mdisp: integer columns show 0 decimal places, mixed columns show fracdig decimal places (trailing zeros kept, so money keeps its cents), and a column of fractions, all values below 1 in magnitude, shows at most allfrac decimal places: the digits that are zero in every value of the column are dropped ("Ignore all 0 digits in column of fractions", mdisp.m), so 0.45 and 0.449 print as 0.450 and 0.449, and 0.5 and 0.25 as 0.50 and 0.25. Exactly: the column prints with the smallest k from 1 to allfrac for which abs(v) * 10.0^k equals an integer in floating point for every finite value v of the column, and with allfrac places when there is no such k. A NaN or missing in the column leaves it at allfrac places, as in mdisp, and an Inf takes no part. Whole parts of 1,000 or more get comma separators, and a value of any magnitude prints its own digits (never scientific notation). NaN and missing display as blank, Inf and -Inf as Inf and -Inf, a Bool as true or false, and any other non-numeric value (a String, a Symbol) as its text. The row_title keyword places a header in the upper-left corner of the table (the row-label column header).

Decimal places per column

fracdig and allfrac are one integer for every column, or a specification for each:

  • a vector with one entry per column, for the matrix and vector methods (a vector has one column);
  • a NamedTuple or a Dict keyed by column name, for a DataFrame; a column it does not name keeps the default (2 and 4), and a name that is no column is an ArgumentError.

A column named in a fracdig specification shows that many places at most, whatever its values: for a column of fractions too, unless allfrac names it as well, so fracdig = (rmse = 5,) gives a column of small values five places. allfrac names only the columns of fractions.

Matrix method

prt(X::AbstractMatrix; rows=1:size(X,1), cols=1:size(X,2), title="", fracdig=2, allfrac=4, row_title="", str=false)

Vector method

prt(v::AbstractVector; rows=1:length(v), title="", fracdig=2, allfrac=4, row_title="", str=false)

DataFrame method

prt(df::AbstractDataFrame; rows=nothing, title="", fracdig=2, allfrac=4, row_title="", str=false)

A DataFrame column is text when its element type (ignoring missing) is a String, a Symbol, a Char or any other non-numeric type, and numeric otherwise (Bool columns are numeric columns that print true and false). A frame with only numeric columns prints with row numbers 1:nrow(df) as row labels, as a matrix does; a frame with any text column prints without row labels. rows overrides either default.

With str=true, returns the formatted table as a string (separator lines stripped) instead of printing. Default behavior prints to stdout and returns nothing.

  • Road networks: thin, addconnectors, links2graph, shortestpaths, tracepath, pathroads, x2ln, cropnetwork, prune_reindex, and osm_roads for OpenStreetMap (a download needs LightOSM), which joinroads joins to the U.S. road network.
  • Routing: segcost, rteTC, rte2loc, isorigin, rte2ldmx, rtesegsum, rte2idx, sh2rte, mincostinsert, twoopt, pairwisesavings, savings.
  • Data and geocoding: usplace, usstate, uscounty, uscentract, uscenblkgrp, uszcta5, uszcta3, uscbsa, uscsa, st2fips, fips2st, faf5nodes, faf5links, usrdnode, usrdlink, usrdnodemap, loc2lonlat, lonlat2loc, lonlat.
  • Maps and plots: makemap and plotroads! (GeoMakie); plotroute!, plotshmt! and aligntext(ax, x, y, labels) (Makie, which CairoMakie loads); mapbbox, aligntext(x, y), alloclines and ldlabel (core); dcf (deprecated, removed in v0.4.0); and the constants WORLD_LIMITS, US_LIMITS, CUS_LIMITS.
  • Display: prt, snapvals, thousands.
  • Public, not exported (called as Logjam.name, so a script's own function of the name does not collide): scanTW, usstates, the inventory measures poissoncdf, pi0, qbar and poissarr, shtr, the sh and tr contract, and the models TSP (with subtours) and binpack, which need JuMP and HiGHS.

Dependencies

Always loaded: Serialization, Artifacts, LazyArtifacts, Random, DataFrames, CSV, DelaunayTriangulation, Graphs, SimpleWeightedGraphs, SparseArrays, Optim.

Weak dependencies, which activate an extension when loaded: GeoMakie (with CairoMakie to render) for maps; Makie, which CairoMakie loads, for aligntext(ax, x, y, labels), plotroute! and plotshmt!; HTTP and JSON3 for street-address geocoding with Nominatim; LightOSM to download an OpenStreetMap road network; JuMP and HiGHS together for TSP, binpack, and snapvals on JuMP variables.
